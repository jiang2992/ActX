# 项目介绍

## 开发背景

### Java 企业项目的智能化困境

在当今的企业级应用开发领域，Java 依然是使用最广泛的技术栈之一。大量的企业项目基于 Java 构建，承载着核心业务逻辑。然而，随着 AI 技术的快速发展，尤其是大语言模型（LLM）和智能体（Agent）技术的普及，Java 生态在智能体领域的建设却远远落后于 Python。

Python 凭借其丰富的 AI 生态（如 LangChain、AutoGPT、CrewAI 等），已经成为智能体开发的首选语言。而 Java 开发者在面对「给现有项目接入智能体」这一需求时，往往陷入困境：

### Java 智能体框架的现状

目前 Java 生态中也出现了一些智能体相关的框架，但都存在不同程度的问题：

- **Spring AI**：作为 Spring 官方的 AI 集成框架，提供了基础的模型调用和工具管理能力，但它更偏向于底层能力封装，缺乏完整的智能体编排、任务分解、业务认知等上层能力，开发者需要自行构建大量业务逻辑。

- **LangChain4j**：LangChain 的 Java 移植版本，提供了一定的智能体能力，但整体设计依然偏通用，学习曲线陡峭，且与 Java 企业项目的整合成本较高，很多 Python 生态的特性在 Java 中并不适用。

- **Semantic Kernel (Java 版)**：微软推出的 AI 编排框架，虽然有不错的抽象设计，但 Java 版本相对较新，社区生态薄弱，文档和示例不足，实际落地困难。

- **其他框架**：如 Jlama、Deep Java Library 等，更多聚焦在模型推理层面，距离完整的智能体应用还有较大差距。

### 核心痛点

这些框架普遍存在以下问题：

1. **学习成本高**：需要理解大量新概念和抽象，上手周期长。
2. **接入成本高**：与现有 Java 企业项目的整合需要大量改造工作，侵入性强。
3. **业务整合困难**：框架本身缺乏对企业业务的理解能力，开发者需要手动将业务逻辑与智能体对接，工作量大且容易出错。
4. **生态不成熟**：相比 Python 生态，Java 智能体生态的工具、插件、社区支持都相对匮乏。

### ActX 的诞生

基于以上现状，我们希望打造一个 **以 Java 技术栈为核心的、无侵入的、轻量级的通用业务智能体**。

ActX 的核心目标是：

- **让智能体可以自主认知当前企业项目的业务**：通过数据源、业务文档、项目资料等信息，ActX 能够主动理解和沉淀业务知识，构建知识图谱，从而赋予智能体业务查询和决策能力。
- **零侵入接入**：基于 Spring Boot 构建，通过配置化的方式快速接入现有 Java 项目，不需要对原有代码进行大量改造。
- **开箱即用**：内置多 Agent 协作、复杂任务编排、会话记忆、MCP 工具管理等核心能力，开发者可以专注于业务逻辑的扩展，而非底层框架的搭建。

## 适用场景

### 场景一：快速为现有项目接入智能体并整合业务

如果你已经有一个成熟的 Java 企业项目，希望快速为其接入 AI 智能体能力，ActX 是一个理想的选择。

**典型需求：**

- 希望让现有的业务系统具备智能对话、任务自动化处理等能力。
- 需要智能体能够理解现有业务逻辑，查询业务数据，甚至主动发现业务知识。
- 不想对现有项目进行大规模改造，希望以最低成本完成智能体接入。

**ActX 的优势：**

- **无侵入设计**：通过配置化的方式接入，不需要修改现有项目代码。
- **业务认知能力**：ActX 支持通过数据源、业务文档等信息自主理解业务，构建知识图谱，让智能体真正「懂业务」。
- **快速整合**：内置消息通道扩展支持，可以快速整合飞书、钉钉、微信或企业内部系统。

### 场景二：Java 开发者的专属个人助理二次开发

如果你不懂 Python，但熟悉 Java，并且希望在一套已经整合了基础功能的智能体框架上进行二次开发，打造自己的专属个人助理，ActX 同样适合你。

**典型需求：**

- 希望拥有一个专属的 AI 助理，能够处理日常任务、管理文件、执行代码等。
- 不想从零开始搭建智能体框架，希望在一个成熟的基座上快速开发。
- 对 Python 生态不熟悉，更希望在 Java 技术栈上进行开发。

**ActX 的优势：**

- **纯 Java 技术栈**：基于 Spring Boot + Spring AI 构建，Java 开发者可以无缝上手。
- **完善的基座能力**：内置多 Agent 协作、复杂任务编排、文件管理、沙箱隔离、MCP 工具管理等基础功能，开发者可以专注于业务逻辑的实现。
- **高扩展性**：通过插件机制、消息通道、自定义 Agent 等扩展点，可以灵活定制自己的专属功能。
- **低学习曲线**：相比其他智能体框架，ActX 的设计更加贴近 Java 开发者的习惯，上手更快。

## 技术栈

- **核心框架**：Spring Boot 3.2 / Spring AI 1.1
- **JDK 版本**：JDK 17+（支持 JDK 21、JDK 25）
- **存储层**：SQLite（本地存储）/ Neo4j（知识图谱存储）
- **沙箱环境**：OpenSandbox（代码执行隔离）
- **构建工具**：Maven 3.6+

---

## 核心能力

| 能力 | 说明 |
|---|---|
| **多模型** | 基于 Spring AI 框架，支持市面上所有主流大语言模型 |
| **多 Agent** | 多 Agent 协作，各司其职，内置 9 个核心 Agent，支持自定义管理 |
| **渐进式工具** | 工具采用二阶段加载，任务过程按需加载工具包 |
| **会话记忆** | 基于会话的上下文记忆，长会话自动总结摘要 |
| **MCP 管理** | 支持多模式 MCP 工具接入，连接外部 MCP 工具服务器 |
| **复杂任务** | 完整的任务执行体系，支持评估、规划、调度、执行、评审、总结，完善的任务评估、节点评审、重试机制 |
| **文件管理** | 为 Agent 提供完整的文件操作支持，完善的文件权限控制 |
| **沙箱隔离** | 基于 OpenSandbox 提供安全隔离的代码执行环境，支持快速沙箱和短期沙箱 |
| **业务认知** | 支持通过数据源、业务资料等信息进行业务知识沉淀，构建知识图谱 |
| **知识查询** | 基于知识图谱进行数据查询，支持语句安全审查、权限控制等 |
| **扩展插件** | 通过统一标准接口实现智能体的能力扩展，不同 Agent 可配置不同的插件 |
| **消息通道** | 消息通道扩展支持，由消息事件驱动，支持快速整合飞书、钉钉、微信或企业内部系统 |
